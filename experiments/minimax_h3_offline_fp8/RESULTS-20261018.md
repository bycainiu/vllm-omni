# MiniMax H3 offline FP8 + AdaLN pruning: 8×RTX 5090 A/B (2026-10-18)

## Conclusion

The standalone offline FP8 run was slower than BF16. The matched 8-GPU run in
this report shows that FP8 is faster when combined with the exact AdaLN schedule
cache and weight pruning: median E2E improved by **14.3%**, median denoise by
**16.2%**, and sampled peak GPU memory during denoising fell by about
**4.5 GiB per card**. The FP8 output remains visibly different from BF16
(SSIM 0.876066, PSNR 28.567949 dB). This combination has not been compared
against the best BF16 fused-QKV configuration, so it is an optional candidate,
not a replacement for the quality-preserving default.

## Controlled A/B

Both variants used the same source tree and runtime/cache configuration. Only
the model weights differed: original BF16 versus the offline ModelOpt-compatible
E4M3 checkpoint.

- 8×RTX 5090, TP4×USP2, strict Ulysses, 480×320, 124 frames, 24 fps, 50 steps,
  seed 1101.
- `vllm/vllm-omni:nightly`, image
  `sha256:3f1af149f06af0b323db4fc4c612adc55e18129b9f25dbc49547264e0dcf4c7e`.
- 50 DLO-resident DiT layers, CPU offload disabled, eager execution, CUDNN
  attention, 2×2-step warmups, 3×50-step formal requests, profiler disabled for
  all formal timing.
- Cache config enables `minimax_h3_adaln_cache` and
  `minimax_h3_adaln_prune_weights` with `min_steps=50`; fused AdaLN-QKV and
  final-norm fusion are disabled in both variants.

FP8 is 14.3% faster E2E and 16.2% faster in denoising than the same-source
BF16 control. The denoise-event durations match across all eight ranks to within
about 1 ms per request. All six requests returned HTTP 200. GPU clocks and the
reported clock-event mask were comparable between variants.

### GPU memory

One-second `nvidia-smi` samples during the denoise interval show the following
per-card high-water marks:

| Variant | GPU 0 | GPUs 1–3 | GPUs 4–7 |
|---|---:|---:|---:|
| FP8 + AdaLN cache/pruning | 9,450 MiB | 7,838 MiB | 7,836 MiB |
| BF16 + same AdaLN config | 14,048 MiB | 12,418 MiB | 12,458 MiB |

This is a reduction of roughly 4,600 MiB (4.5 GiB) per card while the DiT is
running. The maximum sampled usage over the entire request is nearly the same
for both variants because it occurs a few seconds after denoising, during VAE
decode. The whole-request high-water mark therefore hides the FP8 DiT memory
reduction.

## Why standalone FP8 regressed, and what changed

A no-profiler standalone A/B on 2026-10-18, before enabling the AdaLN cache and
pruning, measured FP8 at 54.077 s E2E / 46.995 s denoise and BF16 at 49.698 s /
42.059 s. FP8 was slower by 8.8% / 11.7% on that source/config.

The corrected 50-step rank-0 PyTorch profile confirms the FP8 GEMM path is not
the slow kernel: `cutlass_scaled_mm` used 3.670 s over 10,000 calls, compared
with BF16 `aten::mm` at 7.111 s over 10,400 calls. The profile showed similar
`all_reduce` time (24.387 s FP8, 24.839 s BF16) and a much longer FP8
`all_to_all` event total (13.634 s versus 4.855 s). Those CUDA event totals are
affected by stream overlap and profiler instrumentation; they identify the
communication path as the likely bottleneck but do not prove that A2A alone
caused the no-profiler slowdown.

The fix was to make the exact NPU-inspired AdaLN schedule/pruning path usable
with the selective ModelOpt checkpoint. AdaLN and its projections remain BF16
and unquantized; construction now permits pruning only when that condition is
verified. The integrated runtime logged the precompute/pruning path on all
eight ranks. Earlier HTA/profile validation of this exact pruning approach
showed about 2,500 fewer AdaLN-related all-reduces per rank and request. The
matched no-profiler A/B above then confirms that FP8+pruning beats BF16+the same
pruning configuration.

The current benchmark still disables fused AdaLN-QKV because that kernel
requires BF16 QKV weights. A future selective-export variant that retains QKV in
BF16 may allow this FP8 speedup to combine with fused QKV, but it needs its own
matched 8-GPU and quality validation.

## Code and validation

The source copy is `adaln-qkv-tile64-20261016`. This change:

- validates that AdaLN projections remain unquantized before allowing pruning
  with a non-null selective quantization config;
- maps offline QKV scale rows through the same permutation as QKV weights and
  splits FC1 scales alongside the gate/up weight shards;
- keeps the serving-time AdaLN cache config explicit, with fused QKV disabled.
